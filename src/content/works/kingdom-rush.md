## 작업 개요

킹덤러쉬의 기존 영웅 **이그누스**의 UI·전투·성장 규칙을 역기획하고, 원거리 공격과 늑대 소환을 결합한 신규 영웅 **칸**(Khan)을 기획했습니다.

**칸의 캐릭터 콘셉트와 외형을 직접 디자인하고, 콘셉트 이미지를 그렸습니다.** 가정한 유저 니즈를 바탕으로 전투 역할을 정하고, 부메랑 공격과 늑대 소환의 동작·성장·재사용 조건을 구체화했습니다.

두 영웅의 능력과 스킬은 공통 데이터 구조로 정의했습니다. 기본 능력치와 레벨별 성장, 스킬·소환수, UI·리소스 데이터를 하나의 Excel 파일에 8개 시트로 나누어 작성했습니다.

## 기존 영웅 분석 — 이그누스

이그누스는 근접 공격을 중심으로, 돌진과 주변 광역 공격을 사용하는 영웅입니다. 역기획에서는 불을 소재로 한 캐릭터 콘셉트가 이동·공격·스킬 연출에 어떻게 반영되는지 살펴보고, 공격 범위·피해량·체력 회복과 레벨별 성장 규칙을 정리했습니다.

| 분석 대상 | 문서에 정리한 내용 | 데이터로 구분한 항목 |
| --- | --- | --- |
| 기본 공격 | 적을 인식하고 근접 공격 위치로 이동한 뒤 주먹으로 공격하는 흐름 | 인식 범위, 근접 공격 범위·속도 |
| 돌진 스킬 | 불덩이로 변해 돌진하며 경로의 적에게 피해를 주는 동작 | 스킬 유형, 사용 범위, 피해량 |
| 광역·회복 스킬 | 주변 적을 공격하면서 자신의 체력을 회복하는 동작 | 공격 범위, 피해량, 회복 값 |
| 레벨 성장 | 영웅 레벨에 따른 체력·공격력과 스킬 단계 변화 | 영웅 코드, 레벨, 능력치, 스킬 레벨 |

영웅 선택 화면에 표시하는 요약 능력치와 전투 중 적용하는 레벨별 수치도 구분했습니다. UI용 데이터는 이미지·이름·설명·해금 조건을 관리하고, 전투 데이터는 기본 행동과 성장에 필요한 값을 관리하도록 구성했습니다.

## 신규 영웅 기획 — 칸

### 가정한 유저 니즈와 기획 의도

신규 영웅을 추가할 때 확인해야 할 유저 니즈를 가정하고, 이를 영웅의 역할과 획득 방식에 연결했습니다. **무료 영웅의 선택 폭, 원거리 공격 중심의 플레이, 여러 상황에 대응할 수 있는 능력, 개성 있는 외형과 서사**를 기획의 출발점으로 삼았습니다.

※ 원본 기획서의 유저 니즈와 설문 그래프는 기획 과정을 설명하기 위한 가상 예시입니다. 실제 이용자를 대상으로 조사한 결과가 아닙니다.

| 가정한 요구 | 칸의 기획 방향 |
| --- | --- |
| 결제 없이 선택할 수 있는 영웅 | 스테이지 진행으로 해금하는 일반 등급 영웅 |
| 원거리 공격이 중심인 영웅 | 부메랑을 사용하는 원거리 메인 딜러 |
| 적의 진입과 여러 전선에 대응하는 능력 | 늑대의 이동 차단과 본체의 높은 기동성 |
| 기억에 남는 외형과 서사 | 늑대를 타고 동맹 왕국을 돕는 부족장 콘셉트 |

![가정한 니즈를 일반 등급·원거리 공격·소환 스킬로 연결한 기획 의도](/planning/kingdom-khan-intent.png "신규 영웅 기획서 4쪽 — 가정한 유저 니즈를 영웅의 역할과 능력으로 구체화했습니다.")

### 칸의 콘셉트와 전투 역할

칸은 늑대를 타고 이동하며 거대한 부메랑으로 공격하는 영웅입니다. 근접 공격력은 낮게 두고, 소환한 늑대가 지상 적의 이동을 막는 동안 칸이 원거리 공격을 이어가도록 기획했습니다.

소환한 늑대는 칸을 따라 이동하므로, 칸의 위치 선택이 소환수의 배치에도 영향을 줍니다. 높은 기동성으로 지원이 필요한 전선에 합류하고, 늑대로 적을 붙잡으며 공격하는 운용을 의도했습니다.

![직접 그린 신규 영웅 칸의 콘셉트 이미지와 능력 방향·해금 조건](/planning/kingdom-khan-overview.png "신규 영웅 기획서 5쪽 — 원거리 공격과 기동성, 늑대 소환을 중심으로 구성한 영웅입니다. 칸의 콘셉트 이미지는 직접 그렸습니다.")

## 핵심 스킬과 운용 규칙

### 부메랑 공격 — The dancing of wolf

**부메랑 공격**(31401)은 칸이 직접 부메랑을 던져 여러 적에게 스플래시 피해를 주는 스킬입니다. 지상·공중 적을 대상으로 하며, 스킬 레벨에 따라 최대 공격 대상 수와 피해량이 달라지도록 정의했습니다.

| 스킬 레벨 | 최대 공격 대상 수 | 최소~최대 피해량 |
| --- | --- | --- |
| 1 | 3 | 30~60 |
| 2 | 5 | 45~75 |
| 3 | 7 | 50~80 |

※ 본문에 소개한 칸과 소환수의 수치는 신규 영웅 기획안의 제안 값입니다.

![칸의 부메랑 공격 방식과 스킬 레벨별 데이터](/planning/kingdom-khan-boomerang.png "신규 영웅 기획서 10쪽 — 칸이 직접 사용하는 다중 대상 공격과 데이터 항목을 연결했습니다.")

### 늑대 소환 — The song of wolf

**늑대 소환**(31402)은 **소환수 코드 41411**의 데이터를 참조하는 스킬입니다. 소환한 늑대는 각각 지상 적 하나의 진입을 막으며 근접 공격을 수행합니다. 공중 적은 공격하지 않습니다.

| 스킬·소환수 레벨 | 최대 늑대 수 | 늑대 체력 | 늑대 근접 피해량 |
| --- | --- | --- | --- |
| 1 | 4 | 250 | 11~18 |
| 2 | 5 | 300 | 14~23 |
| 3 | 6 | 400 | 18~30 |

![늑대 소환 스킬 31402와 소환수 41411의 연결](/planning/kingdom-khan-summon.png "신규 영웅 기획서 11쪽 — 늑대 소환 설명과 레벨별 소환수 데이터입니다.")

재소환 여부는 생존 중인 늑대 수와 대기시간으로 판단하도록 했습니다. 늑대가 최대 마릿수만큼 살아 있으면 다시 소환하지 않고, 부족한 경우에는 대기시간이 지난 뒤 최대 마릿수까지 보충합니다. 최대 4마리 중 1마리가 살아 있다면 다음 소환에서는 3마리를 추가하는 방식입니다.

![늑대의 인식·공격 범위와 재소환 조건을 정리한 도식](/planning/kingdom-khan-summon-rules.png "신규 영웅 기획서 12쪽 — 소환수의 범위와 생존 수에 따른 재소환 조건을 정의했습니다.")

## 데이터 구조 설계

### 영웅·스킬·소환수의 연결

두 영웅의 데이터를 공통 테이블에 작성하고, 영웅 코드로 구분했습니다. 기본 행동과 레벨별 성장을 나누고, 영웅이 사용하는 스킬과 소환수를 각각의 코드로 연결했습니다.

| 단계 | 참조하는 시트·항목 | 칸의 연결 예시 |
| --- | --- | --- |
| 영웅 식별 | Hero_Master · Hero_Code | 14번 영웅 칸 |
| 성장 단계 | Hero_Level_Master · Hero_Code + Hero_Level | 현재 영웅 레벨에 맞는 능력치와 스킬 레벨 확인 |
| 스킬 연결 | Hero_Master · Hero_Skill_Code_1 / 2 | 31401 부메랑 공격 / 31402 늑대 소환 |
| 소환 스킬 | Hero_Skill_Master · Hero_Skill_Code + Hero_Skill_Level | 31402의 Hero_Skill_Value에 소환수 코드 41411 지정 |
| 소환수 능력 | Hero_Summon_Master · Hero_Summon_Code + Hero_Summon_Level | 41411의 레벨별 체력·최대 마릿수·공격력 확인 |

같은 `Hero_Skill_Value` 컬럼도 스킬 유형에 따라 의미가 달라집니다. 부메랑 공격에서는 **최대 공격 대상 수**, 늑대 소환에서는 **소환수 코드**를 입력했습니다. 소환할 늑대의 최대 마릿수는 소환수 테이블의 `Hero_Summon_Value`에서 관리합니다.

### 전투 데이터와 표시·리소스 데이터의 분리

| 시트 | 관리하는 내용 |
| --- | --- |
| Hero_Master | 이동 속도·부활 시간·공격 범위와 사용하는 스킬 코드 |
| Hero_Level_Master | 레벨별 체력·공격력·방어력·스킬 레벨 |
| Hero_Skill_Master | 스킬 유형·범위·대상 수·피해량·회복·소환수 참조 |
| Hero_Summon_Master | 소환수의 능력치·인식 및 공격 범위·최대 마릿수 |
| Hero_UI_Master | 선택 화면의 요약 능력치·이미지·아이콘·해금 조건 |
| Hero_String_Master | 영웅 이름·설명과 UI 문구의 언어별 문자열 |
| Hero_Sounds_Master | 이동·사망 대사의 사운드 경로 |
| Hero_Animation_Master | 대기·이동·공격·스킬 등 동작별 애니메이션 경로 |

![영웅 대기실의 표시 항목과 UI 구성 분석](/planning/kingdom-hero-ui.png "이그누스 역기획서 4쪽 — 영웅 선택 화면의 표시 항목을 정의하고 관련 데이터와 연결했습니다.")

이 구조를 통해 영웅의 전투 수치, 화면에 보여줄 설명, 행동에 사용할 리소스를 나누어 작성했습니다. 신규 영웅은 같은 테이블 구조에 행을 추가하고, 소환수처럼 별도 능력치가 필요한 대상은 참조 코드로 연결하는 방식입니다.
