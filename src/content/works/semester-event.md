## 기획 배경 및 목적

‘맙소사 벌써 종강이라니’는 **학업으로 게임을 쉬었던 대학생 유저의 복귀를 유도하는 글자 수집 이벤트**입니다. ‘어른들의 여름 방학’을 콘셉트로, 기존 콘텐츠를 플레이하며 열 글자를 모으고 종강 기념 보상으로 교환하는 흐름을 기획했습니다.

복귀한 유저가 출석·시나리오·아레나·던전·소환을 다시 경험하도록 참여 조건을 연결하고, 글자를 얻을 때마다 성장에 사용할 보상을 함께 제공했습니다. 이벤트 화면과 규칙을 기획서에 정리하고, 퀘스트·확률·보상·상점·UI를 8개 데이터 시트와 JSON 자료로 구체화했습니다.

#### 기획 의도 및 방향성

- **종강을 복귀의 계기로 활용:** 대학생에게 익숙한 종강과 여름 방학을 주제로, 한동안 쉬었던 게임에 다시 접속할 이유 제시
- **기존 콘텐츠로 이어지는 참여:** 출석과 여러 플레이 활동을 하나의 이벤트 재화로 연결해, 익숙한 콘텐츠를 즐기면서 수집 목표도 진행하도록 구성
- **수집 과정과 완성에 각각 보상:** 글자 획득 시의 추가 보상, 열 글자 완성 보상, 뱃지 누적 보상을 나누어 단기 보상과 반복 참여 목표 제공
- **중복 획득을 활용하는 선택지:** 남는 같은 글자 3개를 원하는 글자 1개로 바꿔, 부족한 글자를 직접 채울 수 있도록 설계

## 핵심 시스템 구조

### 포인트에서 뱃지까지 이어지는 수집

플레이어는 퀘스트로 종강 포인트를 모아 글자 상자를 열고, **‘맙·소·사·벌·써·종·강·이·라·니’ 10종을 수집**합니다. 같은 글자가 반복해서 나오면 NPC에게 교환하고, 열 글자를 모두 모으면 종강 뱃지 1개를 얻습니다. 뱃지는 이벤트 상점의 교환 재화이면서 누적 보상의 달성 기준입니다.

![이벤트 확인부터 포인트 획득, 글자 상자, 글자 교환, 누적 보상, 상점으로 이어지는 진행 흐름](/planning/semester-doc-flow.png "이벤트 진행 흐름 — 기획서 5쪽의 화면 구성과 참여 순서입니다. 실제 서비스 화면이 아닌 기획용 UI 시안입니다.")

이벤트 웹 페이지는 수집 현황·퀘스트·글자 상자·누적 보상의 네 탭으로 나누었습니다. 게임 화면의 이벤트 아이콘으로 진입하고, 수집 현황에서는 글자별 보유 여부를 색과 수량으로 함께 보여 줍니다. NPC 교환과 이벤트 상점은 인게임 기능으로 연결했습니다.

### 기존 플레이를 연결하는 퀘스트

매일 한 번 참여하는 출석, 횟수 제한이 있는 아레나·던전, 반복 참여할 수 있는 시나리오·소환을 구분했습니다. 플레이 방식마다 달성 조건과 보상을 따로 두되, 모두 **종강 포인트**를 지급해 같은 수집 목표로 이어지도록 했습니다.

| 참여 활동 | 완료 조건 | 1회 보상 | 획득 제한 |
| --- | --- | --- | --- |
| 출석 체크 | 출석 1회 | 50포인트 | 1일 1회 |
| 시나리오 | 10회 플레이 | 10포인트 | 제한 없음 |
| 아레나 | 대전 10회 승리 | 30포인트 | 1일 3회 |
| 던전 | 10회 플레이 | 20포인트 | 1일 3회 |
| 소환수 뽑기 | 5회 소환 | 30포인트 | 제한 없음 |

※ 첨부 엑셀의 Quest_Master에서 이벤트 퀘스트 301~305를 발췌했습니다.

![이벤트 퀘스트별 진행도와 포인트 수령 상태를 표시하는 화면](/planning/semester-doc-quests.png "종강 포인트 — 퀘스트별 진행도·횟수 제한·보상을 한 화면에서 확인하는 UI 시안입니다. 기획서 10쪽 발췌.")

퀘스트 이동 버튼은 해당 콘텐츠로 연결하고, 조건을 채우면 포인트 받기 버튼을 활성화합니다. 출석은 체크 상태로, 다른 퀘스트는 진행 수치와 남은 수령 기회로 구분했습니다. 반복 가능 여부·일일 횟수·초기화 방식은 퀘스트 데이터에서 관리합니다.

### 글자 상자와 획득 보상

**종강 포인트 100개로 글자 상자 1개**를 교환합니다. 포인트가 부족한 경우에는 보석 10개로 ‘종강 기념 글자 상자 열쇠’를 구매해 글자를 얻는 경로도 마련했습니다. 포인트가 100개 미만이면 상자 교환 버튼을 비활성화하고, 교환이 끝나면 남은 포인트를 갱신합니다.

![종강 포인트를 글자 상자로 교환하거나 보석으로 열쇠를 구매하는 화면](/planning/semester-doc-box.png "글자 획득 경로 — 포인트 상자와 보석으로 구매하는 열쇠를 구분했습니다. 기획서 14쪽의 UI 시안입니다.")

두 경로의 **글자 확률과 추가 보상은 동일**합니다. 상자·열쇠에서 글자 1개를 얻으면 그 글자에 연결된 골드·소환권·에너지 등의 보상도 함께 지급합니다. 열 글자를 모두 모으기 전에도 수집 행동이 성장 보상으로 돌아오게 한 구성입니다.

글자 확률은 균등하게 두지 않고 가중치로 관리했습니다. 두 추첨 그룹의 가중치 합은 각각 5,500이며, 예를 들어 ‘맙’은 1,000/5,500으로 약 18.18%, ‘이’는 100/5,500으로 약 1.82%입니다. 부족한 글자를 채우는 수단은 아래의 NPC 교환과 함께 구성했습니다.

| 획득 글자 예시 | 함께 받는 보상 | 데이터의 연결 |
| --- | --- | --- |
| 맙 | 골드 500 | 글자 50001 → 보상 2 |
| 사 | 3~4성 소환권 1개 | 글자 50003 → 보상 61001 |
| 이 | 보석 10개 | 글자 50008 → 보상 1 |
| 니 | 소환수 최대레벨 성장권 1개 | 글자 50010 → 보상 62004 |

※ Event_WordsBox_Master와 Event_WordsBox_Key_Master의 보상 예시입니다. 확률은 Gacha_Master의 그룹 30001·30002를 기준으로 계산했습니다.

### 중복 글자를 원하는 글자로 교환

무작위 획득만으로 수집을 완성해야 하는 부담을 줄이기 위해, **같은 글자 3개를 소모하면 원하는 글자 1개를 받는 NPC 교환**을 기획했습니다. 원하는 글자의 행에서 비용으로 쓸 글자를 선택하고, 보유량이 3개 이상일 때만 교환 버튼을 활성화합니다.

예를 들어 ‘라’가 없고 ‘맙’이 4개라면, ‘맙’ 3개를 사용해 ‘라’ 1개를 얻고 ‘맙’ 1개를 남길 수 있습니다. 부족한 글자를 채우는 동시에 이미 모은 글자를 유지할지 판단하는 선택입니다.

![원하는 글자와 비용으로 사용할 글자를 선택하는 NPC 교환 화면](/planning/semester-doc-exchange.png "글자 변환 — 받을 글자, 사용할 글자, 교환 비용과 보유량을 함께 보여 줍니다. 기획서 19쪽의 UI 시안입니다.")

NPC 교환으로 얻은 글자는 상자·열쇠에서 얻은 글자와 같은 수집 아이템이지만, **추가 보상은 지급하지 않습니다.** 획득 경로에 따라 추가 보상 지급 여부를 구분해, 교환은 수집을 완성하는 역할을 맡도록 했습니다.

### 누적 보상과 이벤트 상점

열 글자를 모아 받는 종강 뱃지에는 두 가지 쓰임을 두었습니다. 보유한 뱃지는 상점에서 쓰고, **누적 획득량은 1·3·5·7개 단위의 보상 목표**로 사용합니다. 현재 보유량과 누적 달성을 구분한 구조입니다.

| 뱃지 누적 획득 | 누적 보상 |
| --- | --- |
| 1개 | 골드 100,000 |
| 3개 | 3~4성 소환권 5개 |
| 5개 | 3~4성 소환권 10개 |
| 7개 | 4~5성 소환권 1개 |

![종강 뱃지 누적 획득량에 따른 네 단계 보상 화면](/planning/semester-doc-milestones.png "누적 보상 — 달성한 단계의 보상을 한 번씩 수령하는 UI 시안입니다. 기획서 22쪽 발췌.")

상점은 열쇠·보석을 구매하는 **상시 상품**과, 종강 뱃지로 교환하는 **비밀 상점**으로 나누었습니다. 비밀 상점은 코스튬·펫·탈것·던전 입장권·포션의 다섯 슬롯으로 구성하고, 슬롯별 후보 중 상품을 선정합니다.

상품이 입고될 때 구매 비용도 정해진 최솟값과 최댓값 사이에서 결정합니다. 최저 비용에는 BIG SALE, 구매한 상품에는 구매 완료 표시를 붙이며, **60분마다 상품과 가격을 갱신**하고 남은 시간을 보여 주도록 했습니다.

![상시 상품과 다섯 슬롯의 비밀 상점으로 구성한 이벤트 상점 화면](/planning/semester-doc-shop.png "이벤트 상점 — 보유 재화, 구매 상태, 다음 입고까지 남은 시간을 표시합니다. 기획서 24쪽의 UI 시안입니다.")

### 참여 종료와 교환 종료를 나눈 운영

기획상의 운영 기간은 **2024년 6월 16일 오전 6시부터 7월 16일 오전 6시까지**입니다. 퀘스트는 7월 9일 오전 6시에 먼저 종료하고, 상점은 일주일 더 열어 획득한 보상을 교환할 시간을 주었습니다.

퀘스트와 상점의 시작·종료 일시 및 활성 상태를 각각 관리합니다. 참여를 끝내는 시점과 재화를 사용하는 시점을 나눠, 마지막 날에 참여한 유저도 남은 뱃지를 정리할 수 있도록 한 운영 규칙입니다.

### 하나의 보상이 데이터로 이어지는 예

‘사’ 글자를 받는 경우, 상자 테이블은 **비용 100포인트·글자 코드 50003·추가 보상 코드 61001·수량 1**을 정의합니다. 추첨 확률은 Gacha_Master에, 아이템 이름과 속성은 Item_Master에 두었습니다. 보상 구성을 바꾸는 작업과 추첨 비중을 조정하는 작업을 분리한 사례입니다.

```json
{
  "Trade_Code": 50012,
  "Reward_Cost_1": 50014,
  "Reward_Cost_1_Amount": 100,
  "Open_Reward_Code": 50003,
  "Bonus_Reward_Code": 61001,
  "Get_Bonus_Value": 1,
  "Bonus_Reward_Stat": true
}
```

※ 제공된 Event_WordsBox_Master.json의 ‘사’ 행에서 설명용 Name 필드를 제외한 발췌입니다. 50012는 글자 상자, 50014는 종강 포인트, 61001은 3~4성 소환권입니다.
